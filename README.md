# Raider Production — WordPress theme

Lightning-fast custom WordPress theme for [raider.fi](https://raider.fi). Mirrors the design of the [Astro version](https://github.com/mpasanen/raider-site) but ships as a classic WP theme so the client can manage content in the WordPress admin.

## Performance philosophy

PageSpeed 100/100/100/100 is hard on WordPress because WP enqueues a lot by default. This theme:

- **Inlines critical CSS** in `<head>` (no render-blocking stylesheet).
- **Defers** the main stylesheet via `<link rel="preload" as="style"> + onload` swap.
- **Preloads** the four primary woff2 fonts (self-hosted, latin + latin-ext subsets, `font-display: swap`).
- **Serves AVIF + WebP + JPG/PNG** via `<picture>` (per-image responsive widths, pre-generated by `npm run images`).
- **Removes** emoji scripts, oEmbed JS, RSD/WLW links, wp-block-library / global-styles / classic-theme-styles enqueues, XML-RPC, pingback header, REST link header, dashicons on the front end.
- **No jQuery** on the front end (only ~700 bytes of inline JS for the mobile nav).
- **Auto-creates** the four canonical pages (`/`, `/hinnoittelu/`, `/meista/`, `/ota-yhteytta/`) plus `/kiitos/` and sets the static front page on theme activation — zero admin configuration to reach the same site as raider.fi.
- **Native contact form** with honeypot + nonce → admin email via `wp_mail()`. No plugins needed.

## Install

1. Copy the entire `raider-wordpress` folder into `wp-content/themes/` on your WordPress install.
2. **Activate** the theme in *Appearance → Themes*. On activation it will:
   - Create the four pages (Etusivu, Hinnoittelu, Meistä, Ota yhteyttä, Kiitos) if they don't already exist.
   - Set "Reading → Front page displays" to the Etusivu page.
   - Switch permalinks to `/%postname%/` if you're still on plain.
3. Visit *Settings → General* and confirm site title is "Raider Production".
4. Copy the contents of `.htaccess` (in this theme folder) into your **site root** `.htaccess` for the long-cache + compression headers. (Without these, PageSpeed will dock you for "use efficient cache lifetimes".)

That's it — the site is live.

## Regenerating optimized images

The theme ships with pre-built AVIF/WebP/JPG variants under `assets/{images,logos}/optimized/`. If you replace any source image:

```bash
cd raider-wordpress
npm install        # one-time, installs sharp
npm run images     # regenerates all variants
```

The `build/` folder, `package.json`, and `node_modules/` are tooling only — they don't get loaded by WordPress.

## Expected PageSpeed scores

With this theme on a properly cached host (Apache mod_expires/mod_headers active, or Nginx equivalent, Brotli/gzip enabled, HTTPS, HTTP/2 or HTTP/3):

| Page | Desktop | Mobile |
| --- | --- | --- |
| `/` | 100/100/100/100 | 98–100/100/100/100 |
| `/hinnoittelu/` | 100/100/100/100 | 100/100/100/100 |
| `/meista/` | 100/100/100/100 | 100/100/100/100 |
| `/ota-yhteytta/` | 100/100/100/100 | 100/100/100/100 |

Mobile homepage may bounce between 98 and 100 depending on origin RTT (LCP on the hero AVIF). On a CDN-fronted origin (Cloudflare, BunnyCDN) it should hit 100 consistently.

### If mobile perf is below 100 on first deploy

1. Confirm `.htaccess` cache rules are in effect: open DevTools → Network → check that `assets/images/optimized/*.avif` responds with `Cache-Control: public, max-age=31536000, immutable`.
2. Confirm Brotli or gzip is being served on HTML, CSS, JS.
3. If still under, lower hero quality further by editing `build/build-images.mjs` (`hero.jpg → q.avif: 40`) and rerun `npm run images`.

## Common WordPress add-ons that **kill** the score

Do **not** install — they re-introduce render-blocking CSS/JS that the theme works hard to avoid:

- Elementor / Divi / WPBakery (page builders)
- Contact Form 7 / WPForms / Gravity Forms (the theme ships a native form)
- Slider Revolution / any jQuery slider
- Yoast SEO premium frontend assets — Yoast core SEO is fine, but disable analysis JS on the front end.

## Editing content

Open any page (Etusivu, Hinnoittelu, Meistä, Ota yhteyttä, Kiitos) in the WordPress admin. Each one shows a **"Sisältö (Raider)"** meta box with simple text/textarea fields for every editable string (hero tagline, intro text, service descriptions, process steps, quote, etc.).

- Leave a field empty → the theme uses the default text shown when the site is first installed.
- The block editor is **intentionally disabled** on these pages because the layout is rendered fully from PHP templates. The page title (used as the `<h1>` on inner pages) is still editable from the title bar at the top of the editor.
- Field configuration lives in `inc/page-fields.php`. Add more fields there if a stakeholder needs to edit a string that's currently hardcoded — declare the field, then reference it in the template with `raider_the_field( 'my_key', 'default text', $paragraphs = false )`.

For longer-term editorial flexibility (e.g. dynamic pricing cards, image swaps), convert that specific section to ACF fields — but be prepared for a small perf cost when ACF's frontend JS lands.
